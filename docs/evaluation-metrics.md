# TradingAgent 评测指标与质量门禁

本文记录已确认的增量评测方案。执行方式见 [评测设计](evaluation-design.md)，样例格式和启用条件见 [评测集规范](evaluation-datasets.md)。门禁引用 [需求 AT-01 至 AT-12](requirements.md#9-可执行的验收场景) 和 [既有验证分层](architecture.md#9-验证与需求追踪)。

## 1. 判定单位与状态

以 `case_id` 为统计单位。一个样例的多个断言合并为一个结果，重试仍归同一样例，并保留每次尝试和最终状态。预先声明本次所选样例和各门禁的必选样例，运行后列出执行和缺失情况。

| 样例状态 | 含义 |
| --- | --- |
| `pass` | 所有适用断言通过。预期是超时回退、拒绝评分、禁止北交所完整分析或保留部分报告时，观察到约定降级也计通过。 |
| `fail` | 已取得可判定的实际行为，且不符合断言。应记录断言 ID、期望、实际、偏差及证据引用。 |
| `skip` | 所选样例因已记录的前置条件而未执行。按类别或 ID 过滤掉的样例属于未选范围，在门禁覆盖核对中仍须明确。 |
| `error` | 环境、评测器、依赖、超时或无法解析的 Judge 输出使断言不能可靠执行。若产品超时本身是测试对象，按该样例的业务断言判定。 |

每个类别和执行模式分别汇报 `selected`、`pass`、`fail`、`skip`、`error` 以及 `not_run`。中断后未产出结果的已选样例计入 `not_run`，所选总数等于 `pass + fail + skip + error + not_run`。报告可同时显示已判定通过率 `pass / (pass + fail)` 和覆盖率 `(pass + fail) / selected`，空分母记为无数据。缺少必选样例时，即便已判定通过率为 100%，也不能宣告门禁通过。

## 2. 可程序化指标

| 维度 | 指标与断言 | 需求追踪 |
| --- | --- | --- |
| 数据与搜索 | 比较候选的市场与证券代码、前导零、关键匹配与无匹配语义。断言字段类型、单位、观察日与取数时点、来源及映射版本。字段覆盖以该样例的必需字段为分母。 | AT-01、AT-02、AT-08、AT-09 |
| 数据协调 | 记录来源重叠、选中来源、可重试次数、截止状态、缓存时间和冲突字段。以同步屏障和受控时钟断言并行及截止。换序后选用证据一致。重大冲突阻止选用相关证据。 | AT-08、AT-09 |
| 指标 | 黄金样例逐项记录期望值、实际值、单位、有效期、输入引用、公式版本与误差。比较盈利、估值、技术指标及其样本边界。不可计算或不适用的情形核对空值、状态和理由。 | AT-04 至 AT-06 |
| 评分与风险 | 核对分项范围、权重、综合分、风险级别及触发依据。验证合法重配、非法配置、风险阈值边界、核心缺失、行业策略资格和禁止权重重归一。保存规则版本与验证状态。 | AT-07、AT-11、AT-12 |
| Workflow 与持久化 | 逐案断言预期终态、节点偏序、重试上限、重复提交与重启恢复、快照与报告一致性。独立取数允许并行，先后约束只用于有依赖的节点。比较初次提交的不可变字段与保存后的值。 | AT-01、AT-08、AT-10 |
| 报告契约 | 检查 schema、必需维度与明确的不可用原因、事实与计算与推断分类。结构化事实以类型、值、单位、期间和来源引用匹配证据。未授权评级、交易指令、虚构证据、擅改指标或评分等已知负例必须拦截。 | AT-10、AT-11、AT-12 |
| 端到端 | 执行搜索到报告的正常及异常场景。断言证券身份贯通、应有维度、可追溯性、应有降级及异常后的报告可读性。真实接口样例额外记录环境、版本、覆盖、响应时间和失败类型。 | AT-01 至 AT-03、AT-08 至 AT-12 |

标识、资格状态、期间、单位及规则类别用精确断言。金额或比率采用规范指定的十进制精度与舍入点。需要浮点容差的指标在样例中给出 `abs_tol`、`rel_tol` 及依据，按 `abs(actual - expected) <= max(abs_tol, rel_tol * abs(expected))` 判断。零期望值依靠绝对容差。先检查有限值、单位和口径，再比数值。容差沿用 TA-07、TA-10 的经确认规则，不用全局默认掩盖不一致。

同一输入、时点、实现版本和策略版本的重复执行，应得到同样的归一化数值和状态。对比前只剔除预先列出的运行噪声字段，例如生成时间和 UUID，保留业务观察日期、披露版本和证据关系。规则版本或阈值未经确认时，相关样例可用于开发验证，不能作为生产策略已有效的证据。**按规格正确计算评分**与**投资策略具有有效性**独立记录，后者在本评测中的默认状态是未验证，测试通过不赋予投资有效性结论。

## 3. 报告质量与辅助 Judge

确定性校验优先，分别检查输入证据、权威结构化结果和最终输出。逐个验证结构化数据项与对应引用，核心字段冲突、缺失原因被隐藏、篡改数值、错误证券或不允许的结论进入硬门禁负例。自由文本中无法可靠程序化识别的断言进入抽审和 Judge，记录盲区。确定性检查通过只证明已检查的约束满足。

`judge-online` 首版默认关闭，启用时须独立配置并限制调用。固定输入为脱敏的样例指令、冻结分析结果、允许引用的证据及待评报告，加上已版本化的 Rubric。候选文本与证据作为被评材料，提示词明确要求忽略其中嵌入的指令。输出以结构化格式保存每个维度的 0–2 分、简要理由和对应的证据或待复核段落。

| 维度 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 事实一致性与幻觉 | 存在与冻结证据冲突或无依据的具体声明 | 多数相符，个别声明需要补证 | 关键声明均能关联允许的证据 |
| 完整性 | 缺关键维度或遗漏核心缺口 | 覆盖主体，部分降级说明不清楚 | 按场景覆盖必需维度并解释缺口 |
| 风险识别 | 遗漏关键风险或虚构风险 | 识别主要风险，描述证据或限制不充分 | 与已识别风险及其证据、限制一致 |
| 可解释性 | 结论无法关联依据 | 有依据，但结论与证据关系不清楚 | 结论、规则及证据之间关系清楚 |
| 结构和结论边界 | 偏离结构或越过首版结论边界 | 结构可读，事实与推断区分不清楚 | 结构完整，事实、推断与不确定性清楚 |

Judge 结果保存 Judge 模型、配置或可取得的版本、Judge Prompt 版本、Rubric 版本、采样参数、每维分数和理由。业务模型与业务 Prompt 分开记录。缺少证据、返回 schema 无效、Judge 超时或版本不可核验时标记，避免用默认分填补。均值同时公布样本量、分布和低分样例。若仅评价部分案例，覆盖范围随结果一并显示。

使用人工标注的小样本进行初始校准，覆盖好、坏及边界报告。有第二位审核者时独立双评，只有一位时记录单人复核及其局限。人工复核分歧、已知幻觉漏判、异常分数和模型切换样本，并记录人工裁决及理由。首版 Judge 仅观察，人工校准、重复稳定性、误判代价和转硬门禁的阈值需后续确认。

## 4. 分阶段门禁

| 阶段 | 硬性门禁 | 观察性指标 |
| --- | --- | --- |
| M1 回归 | `offline` 的已启用 M1 数据、API、作业状态、重启、基础报告与北交所范围样例全部通过。四维尚未接入时，明确标注不可用且不提供综合分。此门禁覆盖已完成能力。 | 测试耗时、数据异常类型分布和非关键交互体验 |
| MVP 发布 | `offline` 的必选 AT-01 至 AT-12 中可离线断言的部分均通过，涵盖数据正确性、黄金数值、评分资格、Workflow 与报告安全约束。单独完成 `akshare-online` 的 AT-03 和真实数据闭环，若 MVP 包含真实模型叙述，还须完成 `llm-online` 的真实调用闭环和校验冒烟，并验证调用失败时结构化报告保留。正常样例须实际得到通过校验的叙述，失败时保留结构化报告的行为由离线故障样例验证。没有真实验证证据时发布门禁为不完整。 | Judge 各维度得分、延迟分位数、来源故障比例、重试和模型成本 |

`offline`、`akshare-online`、`llm-online` 与 `judge-online` 独立执行和汇报。线上测试使用当次披露或交易日期与独立契约核验，不用固定行情值强行对比。线上因网络、权限或服务中断无法取得可判定证据时，标记 `error`，发布需补证。收到数据且发现字段漂移、数据不实或业务契约违背时，标记 `fail`。线上结果单列采样时间、供应商版本与网络环境，离线 CI 可在无凭据环境执行。

门禁输出 `pass`、`fail` 或 `incomplete`。任一必选断言失败则 `fail`。无必选失败但存在必选跳过、错误、未运行、缺少适用版本或所需线上证据时为 `incomplete`。仅在所有必选样例均通过且覆盖明确时为 `pass`。定向运行只判定所选范围，无法得出整个阶段的发布结论。Judge 分数不抵消硬门禁失败，Judge 缺失也不阻塞首版发布。

### 当前分析与历史能力

范围及补验顺序见 [TA-08 MVP 验收调整](validation/ta08-mvp-scope.md)。

- **L1 当前时点分析**为 MVP 必选能力。AT-03、AT-04、AT-05 的后续验收按拟议的 TA-08-A 核验沪深代表样本。在线报告须显示可追溯的正式披露版本，并以同口径分子分母复算正式估值。正常代表样本须实际完成正式复算。股类、时点或版本证据不足的特殊样本按受影响指标降级，并保留来源估值与冲突记录。
- **L2 历史趋势分析**可按证据覆盖纳入。已开放的趋势须记录版本，并明确标注使用当前可得的修订数据还是恢复了历史当时可见的数据。误标及使用晚于分析基准的数据均触发失败断言。
- **L3 严格历史 PIT 估值**由拟议的 TA-08-B 验收。完整历史披露链、股本有效区间及历史收盘复算属于后续能力。现有 PIT 回归继续检验已实现的版本和时点规则。完整历史复原和历史回测从 MVP 发布必选覆盖中移出。

PV-02 风险阈值和 PV-03 综合风险聚合仍须单独完成样本外验证及人工评审。TA-11 及完整发布门禁继续核验这些生产证据。MVP 新范围适用于后续门禁版本，既有 Manifest 和运行记录按原有口径解释。

## 5. 基准与候选对比

基准来自已保存且可定位的评测运行。按样例 ID、数据集与内容校验值、断言口径、执行模式、环境及相关模型配置对齐。比较代码、评分规则、Prompt 或模型时声明本次变更轴。除该变更轴外应尽量保持其他条件一致。业务评分规则变更应同时说明经批准的预期差异，避免用新评分规则验证旧基准结果。Judge 版本、Judge Prompt 或 Rubric 变化时，两边的文本质量分数需要用同一 Judge 配置重评后再比较。

逐项列出通过转失败、失败转通过、关键数值偏差变化、覆盖变化及新增、移除和不可比样例。必选样例从通过转为跳过、错误或未运行是证据退化，门禁为不完整。数据集改变时，对未修改的可比子集汇报配对结果，其余单列。线上运行若取数或采样条件变化，仅比较契约结果和趋势，并展示环境差异。浏览器、模型及网络相关耗时以秒为单位，并列出样本数和执行环境。未设定发布时限阈值前，耗时、成本、文本评分和覆盖趋势均作为观察指标。
