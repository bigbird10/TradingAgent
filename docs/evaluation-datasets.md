# TradingAgent 评测集规范

状态为增量方案已确认。运行与集成设计见 [evaluation-design.md](evaluation-design.md)，指标和门禁见 [evaluation-metrics.md](evaluation-metrics.md)。本稿中的样例编号为计划，不代表已经实现或通过验收。

## 1. 数据集与运行配置

| 数据集 | 输入 | 预期结果 | 运行边界 |
| --- | --- | --- | --- |
| A 确定性评测集 | 固定名录、原始或标准化行情与财报、交易日历、冻结时钟、故障脚本、计算或评分规则版本 | 可执行断言、独立参考数值、证据 ID、允许的状态转换和降级原因 | `offline` 默认隔离网络，使用 Fixture、Mock Provider、Mock LLM 以及临时 SQLite |
| B LLM 报告评测集 | 冻结的结构化分析、评分依据、缺失及不适用状态、公开参考事实、报告输出约束和 Rubric 版本 | 事实与证据规则、必需章节、应解释的风险、允许推断与禁止断言、人工复核标签 | `offline` 用固定生成结果验证校验与故障回退；`llm-online` 显式调用生成模型；`judge-online` 显式调用 Judge 对已留存的候选文本评分 |
| 在线 AkShare 场景清单 | 市场、证券、接口、相对交易日窗口、环境与超时预算 | 数据身份、单位、口径、来源、业务时效状态、必要覆盖及报告形态 | 仅在 `akshare-online` 运行。价格、财报或行数会变化，断言以业务不变量为主。实测产物须经核对和脱敏后才能晋升为离线 Fixture |

在线结果单独计数。Mock Browser 可作为离线的可选执行环境，真实 AkShare Browser 属于在线配置。任何样例中的实时抓取结果都不能自动覆盖已冻结的预期值。

## 2. Manifest 契约

计划使用 UTF-8 JSON。每个发布版本在 `evals/datasets/<version>/manifest.json` 定义一组可复核样例。Fixture 放在版本目录的 `fixtures/`，也可以引用仓库内由既有验收维护的独立文件。所有引用使用仓库相对路径和内容 SHA-256，运行器核验路径及哈希。禁止目录逃逸、依赖运行时远程 URL 或将 Python 表达式写入断言。既有内联 pytest Fixture 先映射至已收集的 node ID；需要作为正式数据集输入时，把实际输入抽出为共享文件，由原测试和评测共同读取。

| 字段 | 约束 |
| --- | --- |
| `case_id` | 稳定且唯一。行为变体用独立 ID，失败后可按 ID 复跑。 |
| `category` | `data`、`quant`、`workflow`、`llm`、`e2e` 之一。 |
| `description`、`input` | 业务意图与执行输入。证券代码保持字符串，日期与时间带口径，外部数据时点与分析基准分开。 |
| `fixture_reference` | 一组 `path`、`sha256` 和用途。在线样例也引用冻结的请求参数或验收契约文件。 |
| `expected_behavior` | 可读的预期行为，明确正常、部分可用、不可用和失败之间的区别。 |
| `expected_metrics` 或 `expected_assertions` | 至少一项。数值记录期望值、单位、舍入规则和容差；非数值断言记录预期字段、状态、证据或命名校验器。无可用数值时断言缺失状态，不能记作零。 |
| `tags`、`dataset_version` | 标签支持筛选；样例数据集版本须等于 manifest 版本。 |
| `profile`、`gate_scope`、`requirements` | 运行配置，门禁范围（`m1`、`mvp` 或仅观察），以及需求或 AT 编号。 |
| `required_capabilities`、`provenance` | 启用前提、独立预期值来源、审阅状态及相关规则版本。 |
| `pytest_nodeid` | 复用现有测试时的稳定绑定。一个 case 有多个参数变体时使用不同 ID 或明确枚举所绑定子项。 |

Manifest 根记录 `schema_version`、`dataset_version` 和 `cases`。目录版本用语义版本。新增样例升次版本，修订描述且不改变断言可升补丁版本，口径或兼容性变化升主版本。任何修改均发布新版本并保留旧内容；同版本哈希变化必须报错。正式基准与候选使用同一版本及内容哈希。数据集升级时可以对内容、断言和运行条件均未改变的子集做诊断性配对，不据此宣告整版通过。预期改变时应建立新基准，并记录差异、原因和复核，避免用新断言覆盖原回归证据。

## 3. 样例目录与启用边界

下表每行可拆为多个稳定 case ID。M1 只验收已交付的搜索、基础行情、数据契约和部分报告路径。MVP 样例随对应功能实现和规则确认启用。未实现的场景应显示跳过及能力缺口。发布范围要求的场景未执行时门禁为不完整。

| 样例组 | 冻结输入和预期行为 | 通过及失败依据 | 追踪与启用 |
| --- | --- | --- | --- |
| DATA-SEARCH | 固定沪深京名录，分别按代码、名称、关键词查找，含 `000001`、多条「银行」、无匹配及无效输入 | 证券市场和代码正确、搜索不会提交作业；前导零丢失、选错市场、无效与无匹配混淆则失败 | AT-01、AT-02，EV-03 |
| DATA-SCHEMA | 固定原始日线、错误字段或单位、非法交易日期、未来可用日期、过期缓存 | 只接受合格数据并保留原始字段、换算值、日期、来源和取数时间；字段漂移静默通过、缓存时间冒充业务时间则失败 | AT-08、AT-09，EV-03 |
| DATA-PROVIDER | 两个 Mock 同步屏障，调换完成顺序，注入高优先级超时、迟到、全失败及不兼容复权 | 能证明请求重叠，结果按优先级和有效性决定，超时可回退，不可比较结果不混用；顺序影响结果、迟到改写选值则失败 | AT-09，EV-03 |
| E2E-SH-SZ | 各一条成熟沪深非金融标的，搜索、选股、取行情并重新读取报告 | M1 持久化基础报告与数据证据一致；MVP 四维、评分与风险全部按规则输出。作业前置条件失效或报告与快照不符则失败 | AT-01、AT-03、AT-10，EV-03／EV-06 |
| E2E-BJ | 北交所已验证标的，以同一身份分别请求基础行情与完整分析 | 名录和行情可用，完整分析请求返回清晰的未启用状态且不创建作业；错误开放分析或无故禁用行情则失败 | AT-02、AT-03，EV-03 |
| E2E-TIMEOUT | 名录或日线 Mock 超时，含可回退缓存与无合格回退 | 明确区分超时、可重试与未命中。已有证据仍可用于允许的部分输出；超时伪装成空结果、用过期核心数据评分则失败 | AT-02、AT-08、AT-09，EV-03／EV-06 |
| WORKFLOW-RECOVERY | 重复提交、写入失败、进程在确定性报告提交前或后终止 | 状态转换与事务原子性正确，重启保留已提交报告。重复作业、半写入或恢复覆盖快照则失败 | AT-08、AT-10，EV-03 |
| QUANT-FIN | 同口径营收 80→100、负债 120 与资产 200，附晚于基准的财报更正 | 分别核对 25%、60% 和版本过滤；使用未来披露或不同比较口径则失败 | AT-04，TA-07／TA-08、EV-04 |
| QUANT-VAL | 估值适用样本、亏损分母与 EBITDA 不可得；如正式口径批准，市值及分母示例应得 PE 20、PB 4、PS 2 | 数值、适用性、口径及负值原因正确；零除、缺失补零或亏损被正常低估信号覆盖则失败 | AT-05，TA-07／TA-08、EV-04 |
| QUANT-TECH | 收盘价 1 至 60、独立 EMA/RSI 参考序列、短窗口、停牌与休市夹在交易日内 | 第 60 条 MA20 为 50.5、MA60 为 30.5；其余按正式窗口和精度。虚构补点、预热不足计算或复权混用则失败 | AT-06，TA-07／TA-09、EV-04 |
| QUANT-SCORE | 四维 80、70、60、90，权重 35/30/15/20，另有非法权重、风险边界、核心与非核心缺失 | 首组为 76，权重和边界按规则复算，核心缺失停止综合分。门槛绕过、错误聚合或结果不可复算则失败 | AT-07、AT-11，TA-10／TA-11、EV-04 |
| E2E-FIN-MISSING | 去除关键财报字段，分别模拟尚未披露、数据过期或口径异常 | 保留有证据的部分报告并说明原因，综合分缺失；补造值或用同一原因掩盖不同状态则失败 | AT-04、AT-08、AT-11，EV-06 |
| E2E-VAL-LOSS | 对同一普通企业分别令估值指标不适用、发生亏损或缺少 EV/EBITDA 输入 | 正确标记适用性与风险，不因亏损自动得出低估；违规计算、混用分母或编造条件指标则失败 | AT-05、AT-11，EV-06 |
| E2E-FIN-SECTOR | 分别使用银行、证券、保险固定样本，保留有效技术数据并禁用专用规则 | 允许部分报告，综合分保持缺失；通用规则删项重归一化生成综合分则失败 | AT-12，EV-06 |
| E2E-TRADE-STATE | 分别提供已核实 ST、停牌、休市或无证据的日线空档，另有上市历史不足样本 | 状态与证据相符，行情不足说明影响；用空档推断停牌、把风险警示当作停牌或伪造历史点则失败 | AT-06、AT-08，EV-06 |
| E2E-CONFLICT | 主要数据组有重大同口径冲突，其他维度资料齐全 | 保存双方证据，受影响输入降级且其他维度可分析；平均冲突值或生成受阻综合分则失败 | AT-08、AT-09、AT-11，EV-06 |
| E2E-LLM-ERROR | LLM 超时、不可用、返回损坏结构或篡改已有分数，确定性报告已经落库 | 原快照和权威结果保持一致，叙述降级可追溯；污染或隐藏确定性结果则失败 | AT-10，EV-05／EV-06 |
| LLM-CLAIMS | 冻结结构化结果与风险，构造正确叙述、错单位、假新闻、伪证据、遗漏和明确买卖指令 | 校验器接受合理改写、拒绝已定义违规，细粒度语义质量单列观察；捏造事实或交易指令进入已发布报告则失败 | AT-10、RP-02 至 RP-06，EV-05 |

M1 样例优先复用 `tests/contracts/test_market_data.py`、`tests/contracts/test_http.py`、`tests/integration/akshare/test_adapter.py`、`tests/integration/test_ta04_storage.py`、`tests/integration/test_storage_process.py`、`tests/integration/test_sqlite_market_data.py` 和 `tests/e2e/test_research_workflow.py`。真实 AkShare 可复用 `tests/integration/akshare/test_live.py` 和既有在线 HTTP 与 Chrome 验收。 [TA-01 探测记录](validation/akshare-feasibility.md)

### TA-08 补验样例计划

范围及补验顺序见 [TA-08 MVP 验收调整](validation/ta08-mvp-scope.md)。

| 建议样例组 | 级别与模式 | 独立证据及断言 |
| --- | --- | --- |
| CURRENT-FIN-VERSION | L1 · 离线及沪深在线 | 将字段与截至分析基准已公开的正式报表版本逐项绑定，记录报告期、合并范围、单位、修订、披露与可用时间。将营业总收入和营业收入替换、使用未来修订或丢失版本时失败。 |
| CURRENT-VAL-SCOPE | L1 · 离线及沪深在线 | 沪深各至少一只适用普通 A 股，固定最近有效行情时点，独立复算正式 PE、PB、PS。记录股本、库存股、调整和期间证据，分别校验观察与复算值。来源与计算口径冲突须显式披露并按受影响指标降级。 |
| CURRENT-VAL-AH | L1 · 离线及美的集团在线证据复核 | 分别保存 A 股、H 股的股数、库存股处理、价格、币种、计价时间和必要汇率。公司整体股权市值缺证时降级。用 A 股收盘价乘 A/H 总股本即使与供应商值一致也不能通过。股本法律生效时间和披露可用时间单列。 |
| TREND-VERSION-LABEL | L2 · 离线 | 给定原版与事后修订的五洲交通样本。用当前可得修订数据绘制趋势时保留修订版本，标为历史当时可见数据则失败。 |
| HISTORICAL-PIT-REPLAY | L3 · 后续 | 保留现有历史 PIT 回归。完整生产验收覆盖连续历史披露版本、股本和市场行情，拒绝将收盘后才披露的股本变化用于该历史收盘复算。 |

L1 正常样例须完成真实财务及估值核验，特殊样例须证明正确降级。L2 在实际开放时验证版本标识。L3 完整覆盖独立验收。后续按新数据集和门禁版本登记这些样例，保留既有评测记录及原有判定。风险阈值及综合风险聚合仍独立进行样本外验证。

## 4. 黄金值、人工复核与样例晋升

- 数值黄金样例由已确认公式的人工复算、独立参考实现或可引用的公开事实提供。保存输入、计算路径、规则版本、精度和审核记录。待确认的阈值保持待启用。确定性测试验证执行正确性，投资有效性需另有独立验证记录。
- LLM 输入按固定契约冻结结构化分析、证券身份、分析基准、证据清单、允许事实、关键风险、预期章节和禁止断言。参考报告可作为人工认可表达示例。验收针对事实、约束和证据，允许等价表达。
- 将人工审核通过的真实报告转为候选样例时，先脱敏、冻结公开来源和快照，再逐项核对数值、时点、来源、规则、风险和推断边界。保存审核人标识、日期、结论、复核依据和争议处理。模型原文或 Judge 评分单独保存，不能自动晋升为黄金答案。
- 预留开发样例与保留验证样例，按同一证券、报告期或相似场景分组划分，避免近重复跨集合。保留样例只用于候选验证。预期答案、人工标签及 Judge 私有 Rubric 不进入生产模型 Prompt。Judge 接收相同格式的公开证据和候选文本，不暴露模型身份或版本标签；对照评测随机化或平衡呈现顺序。
- 在线样例只发送经校验的公开材料和必要字段。凭据、完整本地数据库、无关日志、路径与未授权私有材料均排除。评测产物保存 Fixture 哈希、版本和可公开的引用，原始供应商异常先脱敏。
