# TradingAgent 评测体系设计

增量方案已确认。基线为 [需求](requirements.md)、[架构](architecture.md) 和 [开发任务](tasks.md)。首批实施范围为 EV-01 至 EV-03。配套见 [评测集规范](evaluation-datasets.md) 和 [指标与质量门禁](evaluation-metrics.md)。

## 1. 当前状态与评测缺口

截至本轮审查，TA-01 至 TA-06 完成，M1 已通过。现有工作流由固定 Python 用例与持久化 Job 编排。TA-07 至 TA-14 未开始，生产财务和估值适配、技术指标、四维分析、风险聚合、评分及 LLM 叙述尚待实现。已有财务取数探测和披露时点校验属于可行性或数据契约证据。

| 现有模块 | 可评测入口与现有证据 | 增量缺口 |
| --- | --- | --- |
| `trading_agent/market_data/providers/akshare/` | `AkShareProvider.fetch`、`capabilities`，以及可注入的 Worker。名录、基础日线和沪深前复权均有固定输入及真实测试。TA-01 的三轮记录用于说明接口覆盖。 | 财报修订、估值及停牌的可执行 Fixture 需随 TA-08/09 补齐。探测输出是抽样证据，仅可从中挑选并核验完整样例。 |
| `market_data/models.py`、`normalization.py`、`coordinator.py` | `normalize`、`find_conflicts`、`Coordinator.resolve` 返回来源尝试、原字段与单位、冲突和选用结果。已有双 Mock、控制时钟和屏障验证。 | 将可重跑的正例和失败样例登记为稳定 case ID。完整失败输入及拒绝原因可从 Resolve 边界采样，勿假设现有报告包含所有候选原始响应。 |
| `application/research.py`、`application/jobs.py` | `ResearchService`、`JobRunner`，可注入 Provider、时钟和分析/叙述回调。HTTP 状态、作业去重、检查点与重启可观测。 | 目前只有作业阶段与选中日线取数摘要，缺少四维节点输入输出、依赖次序、规则/模型版本和失败细分。按功能任务逐项补足。 |
| `storage/runs.py`、`storage/cache.py` | 版本化的快照与报告 JSON、作业终态、来源获取时间及缓存 TTL。M1 快照含证券配置、取数请求、选中日线及来源尝试摘要，可用临时 SQLite 校验一致性。 | 当前持久化没有评测 Run ID、样例版本或版本对比，也没有完整评分和叙述过程记录。评测运行文件独立保存，继续以生产快照作为事实证据。 |

| 四维与 LLM 后续模块 | 设计上将按 TA-07 至 TA-13 交付独立指标规范、确定性指标/评分及统一 LLM 客户端。 | 当前无实现、无黄金指标回归、无真实模型报告质量基线。框架可先用 M1 样例跑通，后续能力由对应任务供给真实评测接口。 |

现有测试按用途划分如下：

- **单元级与契约**。目前没有独立 `tests/unit/` 目录。Provider 解析、行情日期窗口和单位/冲突边界有函数级断言。 `tests/contracts/test_market_data.py` 验证多源规则，`test_http.py` 验证路由契约、输入和安全边界。
- **集成**。 `tests/integration/` 包含 SQLite、子进程终止与作业恢复、缓存与协调器联动、AkShare 适配器以及单独启用的真实 AkShare 接口测试。
- **端到端**。 `tests/e2e/test_research_workflow.py` 验证 HTTP 至持久化，`test_browser.py` 验证 Mock 和真实 AkShare 的 Chrome 流程，两类外部能力均有显式启用条件。TA-06 记录的全量验收为 79 项通过。本轮复跑离线基线为 72 项通过、7 项显式启用用例跳过，仍有一条已知的 Starlette TestClient 弃用警告。两组结果范围均限于现有功能。
- **尚缺**。按稳定样例 ID 选择与聚合、固定输入的跨版本对比、可版本化的数值与叙述评测集、统一结果和质量门禁。

## 2. 集成方式与职责

采用仓库内的轻量本地工具，复用现有 pytest、Mock Provider、时钟注入、HTTP TestClient、临时 SQLite 和可选浏览器。核心业务仍通过现有入口运行。评测侧读取结构化结果和安全快照，写入独立文件。现有常规测试继续独立运行，评测集优先复用测试节点或 Fixture，避免同一断言在两处维护。

| 层 | 执行入口 | 对应验证 |
| --- | --- | --- |
| 数据 | Provider 和 Coordinator，必要时使用 HTTP 搜索及基础报价 | 身份、字段、时点、单位、来源、质量，超时、并发、回退、冲突与缓存时效 |
| 指标及评分 | 随 TA-07 至 TA-11 交付的纯函数或稳定服务入口 | 固定输入与独立黄金结果，支持精确或有声明容差的比较。规则正确性与投资有效性分别记录 |
| Workflow | 真实编排、测试 Provider/模型、临时数据库、故障注入和节点边界观测 | 依赖顺序、重试、终态、恢复、快照与报告一致性。并行分支断言依赖关系，允许合法的不同完成顺序 |
| 叙述质量 | 独立生成接口、冻结分析快照、候选模型或存档输出、规则校验、可选 Judge | 事实与结构化字段一致、覆盖、风险依据、凭据隔离和结论边界。规则通过之后才进入可选文本评价 |
| 端到端 | HTTP 或 Chrome 走正常入口，环境按 profile 隔离 | 已实现的搜索至基础报告先入 M1 门禁，TA-13 后启用四维、评分、模型和特殊标的场景 |

记录优先复用 `Dataset/Resolution`、`Checkpoint`、报告及持久化查询。TA-08/09 提供指标 ID、口径、期间、单位、缺失状态、证据和计算规则版本；TA-11 提供评分/风险规则版本、资格、分项贡献和聚合结果；TA-12 提供脱敏的结构化生成输入、经过校验的输出、生成/降级状态、模型版本、Prompt 版本与校验失败类别；TA-13 关联同次作业的快照和报告。节点顺序优先用测试侧观测器或回调验证。确需观测时仅增加带 run ID 的节点名、逻辑时序、阶段状态及证据引用，保留现有业务状态机。

## 3. 执行与结果

建议使用根目录 `evals/` 存放执行器与版本化数据集，运行产物默认保存到已忽略的 `artifacts/evaluations/<run_id>/`，可用 `--artifacts` 指定其他位置。执行器读取清单，按 case ID 注册可信测试节点或结构化检查器，禁止清单指定任意可执行代码。先校验 ID、版本、输入引用、摘要和 profile，再执行。既有 pytest 结果可通过公开的报告接口或 JUnit 文件转换，严禁解析终端文字来判定硬门禁。可选的浏览器和真实端点保留现有启用方式，由执行器选择明确的用例集合。

| Profile | 运行边界 |
| --- | --- |
| `offline` | 默认。Fixture、Mock、固定时钟和临时数据库。日常回归及未来 CI 使用，默认选无需 Chrome 的关键子集，另可显式运行 Mock 浏览器用例。 |
| `akshare-online` | 显式启用，只访问真实 AkShare 上游。断言业务身份、结构、时间口径和完整性，动态报价不与历史固定价格做等值门禁。 |
| `llm-online` | 显式启用，使用冻结分析输入和经过配置的候选报告模型。确定性检查结果单列，不调用 Judge。 |
| `judge-online` | 显式启用，读取固定的候选报告和参考事实。记录独立 Judge 配置和 Rubric，首版用于观察与人工复核。 |

当前提供 `python -m evals run --profile offline --category data`、`run --case <case_id>`、`run --profile offline --all` 和 `compare --baseline <run_id> --candidate <run_id>`。不同 profile 分次生成结果，发布摘要可聚合同一候选版本的多份证据。每次运行新建目录，原子写入 `run.json`、`summary.md` 与必要的脱敏明细。比较结果列出同组样例的变化、不可比项及其原因，显式输出通过、失败或证据不足。退出码建议 0 为通过，1 为门禁失败，2 为缺少必需证据或执行/配置错误。筛选运行只对所选范围给结论，发布要求由固定清单判定。M1 必选 ID 来自 `evals/gates.json`，替换或筛选数据集不能移除这些必选项。

`run.json` 至少包含 Run ID、开始结束时间及 UTC 时间戳、代码标识、运行环境和依赖摘要、profile、选择范围、数据集版本与摘要、Runner/门禁版本、指标及评分规则版本、候选模型和 Prompt、Judge 模型与 Rubric、样例计数、逐样例状态与证据、分维度结果、基准 Run ID 与可比状态、门禁结论。未涉及版本标为不适用，供应商无法确认的真实模型修订标为未知。当前工作区没有 Git 元数据，首版需支持人工代码标签与按明确文件范围计算的排序内容摘要。有 Git 时记录 commit 与 dirty 状态，含未提交变更时仍保留工作树摘要。日志不保存凭据、数据库全集、请求原文或本地路径。LLM 输入限于审查通过的公开事实及脱敏结构化分析。

## 4. 已确认决策与实施边界

| 决策 | 执行要求 |
| --- | --- |
| 版本管理 | 将执行器及配置、版本化数据集、黄金输入及期望、经审核的参考事实及 Rubric、指标和门禁规则纳入 Git。正式基准仅将审核后的精简摘要纳入 Git。完整运行结果、日志、原始模型请求与响应、快照和缓存默认留在本地，完整产物目录已忽略。 |
| 本地保留 | 手动清理默认预览，只有显式 `--apply` 执行。最近 30 次与最近 30 天取并集，保留任一条件满足的结果。次数和天数可配置。显式标记的正式基准受保护。默认无后台删除。 |
| 离线与在线门禁 | 无外网时仍可执行离线评测。MVP 发布需真实 AkShare 证据，覆盖沪深搜索、日线、财务、估值、字段完整性、时效、单位口径和异常处理。MVP 若包含真实 LLM 叙述，还须有真实调用闭环及故障降级证据。Mock 不能替代上述证据，网络或凭据阻塞导致发布门禁不完整。 |
| Judge | 首版默认关闭，保留独立 profile 和版本字段，EV-05 再评估适配。未来启用需配置独立模型、Prompt、并发、调用次数、预算与出站白名单。无法可靠估算费用时拒绝可能超预算的调用。保留分数、理由和待复核标记。Judge 不进入 MVP 硬门禁。 |
| 指标与投资有效性 | 黄金值采用已确认规范与独立验证来源。投资有效性由独立证据和人工审核判定，策略启用标准仍归 TA-10。 |
| 分批实施 | 先完成 EV-01 至 EV-03。功能任务继续交付对应评测证据，EV-04 至 EV-06 按依赖启用，TA-14 使用 EV-07 的发布证据。 |

当前离线入口使用可信 pytest 注册表和固定输入，子进程不继承真实测试开关或模型凭据。需要强制隔离网络时，可在无外部网络的系统或 CI 执行环境中运行。首批仅覆盖 M1，MVP 门禁保持不完整。日常命令见 [README](../README.md)，功能与评测依赖见 [任务清单](tasks.md)。
