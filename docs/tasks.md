## 2. 开发任务

### TA-01 · AkShare 真实接口可行性验证

- **状态**　已完成。见 [实测报告及证据](validation/akshare-feasibility.md)。沪深当前单股最小闭环的数据条件通过验证。财报历史版本、北交所四维能力和正式参数的限制见报告。

- **目标与依赖**　开发阶段首项，无开发任务依赖。验证沪深主路径，确定北交所可以开放的能力。
- **文件与交付**　`docs/validation/akshare-feasibility.md`、可重跑的 `scripts/probe_akshare.py`、脱敏样本与环境记录。
- **实现内容**　验证沪深主板、科创板、创业板和北交所样本，覆盖成熟非金融、金融、亏损、新股和已知停牌情形。逐组记录名录、最新有效行情、未复权及前复权日线、三表、正式披露与修订、估值、交易日历和停复牌的字段、口径、时间、覆盖及错误。多时点小量采样并记录耗时、限流、空响应及共享上游。基于测量提出业务时效、缓存、并发、重试、超时和冲突容差的初始配置。
- **测试与完成标准**　通过可重跑的实际调用生成 DS-01 证据和市场能力矩阵，记录实测版本、时间、字段缺失、最早及最新记录和启用建议。北交所先验名录和基础行情，完整分析单独验证。沪深必要数据若无法可靠取得，明确标为阻塞并提交 AkShare 内替代接口、显式降级或需求调整选项，处置确认前受影响主路径不得开工。
- **外部依赖与风险**　真实 AkShare 和上游网络必需。DNS、访问限制、字段变动、接口口径不明或采样不充分应记录为未验证或阻塞。

### TA-04 · SQLite、缓存与持久化作业

- **状态**　已完成。macOS 上 12 项存储与协调器集成测试通过，包含并发提交与领取、事务回滚、失败重试、实际子进程被终止后的恢复，以及原始取数时间与缓存期限保留。本地 SQLite 使用 DELETE 日志模式和短事务，避开实测 SQLite 3.45.1 的 WAL 并发缺陷。其他操作系统尚未实测。

- **目标与依赖**　依赖 TA-02、TA-03。作业可轮询、可恢复，报告和快照原子提交。可与 TA-05 并行。
- **文件与交付**　`trading_agent/storage/`、`trading_agent/application/jobs.py`、数据库迁移及持久化集成测试。
- **实现内容**　保存作业、快照、报告和缓存。持久化后由进程内执行器原子领取。限制一个活动作业，处理重复提交、进程中断、终态和重试。缓存 TTL 与业务时效分离。保持缓存淘汰与快照独立。
- **测试与完成标准**　重复提交不产生两个活动作业。模拟服务中断、写事务失败及报告已提交后重启，状态一致且已保存的确定性报告可读。缓存命中保持原始获取时间。
- **外部依赖与风险**　离线。验证本地文件锁、SQLite 并发写入与跨平台进程恢复行为。
